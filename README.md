# Kids Learning for Android and iOS

This repository is the React Native app for Kids Learning, built with Expo SDK 58. Screens use native views, touch controls, Expo Speech, and generated audio. They do not load the website in a WebView.

The website stays in [KidsLearningApp](https://github.com/achyuthaTechSolutions/KidsLearningApp), including the Capacitor Android shell. This app vendors the same lesson rules in `packages/learning-core`. When letters, quiz rules, or achievement checks change, copy `packages/learning-core` between the two repositories so they stay aligned. Browser progress is not copied onto the phone.

The native application id is `app.kidslearning.native`. The Capacitor shell keeps `app.kidslearning.discovery`. They can be installed side by side.

## What the phone app includes

- Home, with continue-learning, today's challenge, and the same progress totals as the website
- Keyboard Explorer, with a touch keyboard and an optional connected keyboard
- Alphabet World, Number World, Animal Kingdom, and My First Words
- Music Studio: piano, xylophone, drums, guitar, flute, and the three built-in songs
- Five learning games and the daily challenge
- Dino Dash, using the shared runner rules
- Achievements and parent settings
- Privacy

Balloon Pop, Memory Match, Word Builder, and the other games named in some planning notes are not in this product. They were not added as new games.

Pictures use the emoji already stored with each lesson. The Fluent SVG files stay with the website.

## Requirements

- Node.js 22 or newer
- For a store binary: an [Expo account](https://expo.dev) and EAS Build
- Android install: Android Studio with an emulator, or a phone with USB debugging, plus the Android SDK
- iOS install: a Mac with Xcode, or EAS Build with an Apple Developer account for a device or App Store build
- This app does not ask for the microphone, camera, or location

## Scripts

```bash
npm install
npm start
npm run android
npm run ios
npm test
npm run typecheck
```

`npm start` opens Metro. In Expo Go, scan the QR code or press `a` / `i`.

`npm run android` and `npm run ios` open Expo Go on a device. iOS needs macOS. Android needs a running emulator or a connected phone.

`npm run android:device` and `npm run ios:device` compile a development build (`expo run`). That needs the Android SDK or Xcode.

## Production builds

Native projects are generated by Expo (Continuous Native Generation). Do not edit `android/` or `ios/` by hand. They are gitignored.

```bash
npx expo prebuild
npx expo run:android
npx expo run:ios
```

Store binaries use EAS. `eas.json` has development, preview, and production profiles. No signing keys are stored in the repo.

```bash
npx eas-cli@latest login
npx eas-cli@latest build --platform android --profile production
npx eas-cli@latest build --platform ios --profile production
```

Android production builds an App Bundle. iOS production needs an Apple team. The preview profile can make an APK for internal install.

A JavaScript bundle for Android and iOS was produced with `npx expo export` during development of the first version. That is not a store binary, and it was not installed on a device or emulator in that environment.

## Speech and sound

- Speech uses Expo Speech and the device's installed voices. The default is "Soft voice (recommended)", which prefers a youthful or soft English voice when one is installed. A parent's saved voice wins when that voice is still on the device.
- Pitch stays near 1.08, a little higher for a deep voice, and is not a cartoon voice.
- Speech rate uses the same 0.5–1.5 scale as the website. Expo Speech treats 1.0 as normal on this SDK. Android and iOS can still sound a little different.
- Volume and mute apply to speech and to sound effects.
- A new line cancels the previous one so instructions do not pile up.
- Leaving a screen or backgrounding the app stops speech and sound.
- Instrument pads write short WAV tones (triangle, sine, and noise) and play them with Expo Audio. Piano, xylophone, guitar, flute, and drums use different waves and envelopes. They are synthesized on the device, the same idea as the website, not recorded samples of acoustic instruments.
- The audio session asks to play in silent mode and to mix with other apps. iOS can still quiet speech with the hardware silent switch or with a voice that is unavailable. That behaviour was not checked on a physical iPhone or Android phone.
- If speech or sound cannot start, the words and pictures stay on screen.

## Progress

Progress and settings are stored with AsyncStorage under the same keys the website uses in localStorage:

- `kids-learning-progress`
- `kids-learning-settings`
- `kids-learning-daily`
- `kids-learning-dino`

Malformed data falls back to the empty lesson state. Reset asks a grown-up a short addition question, then confirms. Reset clears lessons, scores, the streak, badges, today's challenge, and Dino Dash scores. It keeps the dinosaur colour and the sound settings.

Learning progress still has no cloud sync. The app does not ask for the microphone.

## Parent accounts

Sign-in is for a parent or guardian. The phone calls these paths when `EXPO_PUBLIC_API_BASE_URL` is an `https://` address:

- `POST /v1/auth/login`
- `POST /v1/auth/register`
- `POST /v1/auth/forgot`
- `POST /v1/auth/verify`
- `POST /v1/auth/resend`
- `POST /v1/auth/refresh`
- `POST /v1/auth/logout`
- `POST /v1/children`
- `POST /v1/session/child`

No server in this project implements them. A production build, where `__DEV__` is false, reports that account services are unavailable and does not accept a practice login. Tokens are stored with `expo-secure-store`, not AsyncStorage. Passwords are not stored.

`npm start` reads `.env.development`, which sets `EXPO_PUBLIC_AUTH_MODE=mock`. That practice account lives in memory, is not a real login, and is ignored when `__DEV__` is false. The EAS production profile does not set the mock flag.

Welcome, sign in, registration, password help, verification, and child nicknames are translated in English, Telugu, and Hindi. Telugu uses Noto Sans Telugu. Hindi uses Noto Sans Devanagari. Those fonts were not checked on a physical phone or emulator in this environment.

Child profiles store a nickname, an age group, and an animal picture. They do not ask for a child’s email, phone, school, or birth date. Parent settings and sign-out stay behind the existing grown-up question, and that question locks again when the app leaves the foreground.

Before a store release, the product owner still needs a published privacy policy and contact method, a review of India’s DPDP rules, and the Google Play Families and Apple kids requirements. The in-app terms are not that policy.
